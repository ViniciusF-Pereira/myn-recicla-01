Regra de ouro

Reduzir número de chamadas, tokens por chamada e latência são três coisas distintas. Meça as três no seu workflow — não há benchmark independente que as trate como métrica de primeira classe.

Pesquisa: ferramentas que cortam chamadas

Decisão rápida antes de abrir qualquer tabela.

  • Descoberta ampla → Brave LLM Context (US$5/1k, P90 <500 ms) ou Parallel Fast (US$1/1k).
  • Relatório citado → Tavily Research, Exa Deep/Agent, Brave Answers.
  • URL conhecida → r.jina.ai com seletor CSS ou trafilatura/Crawl4AI.
  • Interação → Stagehand + Browserbase; Browser Use V4 com REPL persistente.
  • Coding agent enxuto → Playwright CLI + SKILLs, não MCP cheio de schemas.

OpenCode V2

  • execute roda JS num runtime sem filesystem/imports/timers; fetch disponível.
  • search() descobre ferramentas dentro da mesma chamada — catálogo é parcial.
  • Compactação mantém ~15k tokens recentes; warming preserva cache.
  • MCP V2: mcp.servers, disabled, codemode:true, OAuth, pooling.
  • Negar execute traz schemas completos de volta em toda requisição.

Mecanismos e armadilhas do runtime
Erro de tool inexistente virou promise rejeitada (v2.3.1); VM bytecode experimental em experimental.codemode_vm; call IDs por ferramenta em hooks; namespace chamado como tool sugere até três reais; fetch checa redirects contra regras de webfetch. Algoritmo de search() e tipo exato do sandbox não são documentados publicamente.

SLM de reparo + painel de juízes

Determinístico primeiro, modelo rápido no fallback, maioria decide.

Reparo em 3 camadas

  1. Determinístico: cercas, aspas, vírgulas, argumentos em string.
  2. SLM: groq-fast, 256 tokens, 8 s, timeout oportunista.
  3. Filtro: resposta volta pelo reparo e pelo allowlist de nomes.
